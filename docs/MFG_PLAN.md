# MiniERP2_MFG (제조원가관리) 개발 기획안

작성 2026-10-21. 현황 분석은 [COST_MANAGER_DRAFT.md](COST_MANAGER_DRAFT.md)에 있다. 이 문서는 사용자 답변(2026-10-21)을 반영한 확정 기획안이며, 초안 §3(설계)을 대체한다.

## 0. 사용자 결정 사항

| # | 결정 |
|---|---|
| D1 | 이름은 **MiniERP2_MFG**(약칭 MFG). **단독 실행 프로그램**이다. MiniERP2의 "제조원가" 버튼은 이 프로그램을 실행하기만 한다 |
| D2 | DB는 MiniERP2와 별개인 **mfgdb**를 쓴다. 백업과 DB 관리 체계는 MiniERP2에 준한다 |
| D3 | MFG는 **원료 단위 원가**를 관리한다: 원료별 매입처, 매입가, 이력 |
| D4 | 매입처는 MiniERP2 **채널코드**와 연동한다 |
| D5 | 배합(여러 원료 + 배합비 조정) → 부자재 추가 → **완제품 원가** 계산. **확정**을 누르면 mfgdb에 저장하고, MiniERP2 master DB로 보낼 수 있다 |
| D6 | 초기 제조법은 '제조법관련' 엑셀의 틀로 세팅하되, **전부 미확정 상태로 가져온다.** 사용자가 실사용하면서 확인하고 확정 버튼을 누른다 |
| D7 | 제조법 화면은 kg당 단가와 **용량별 완제품 단가**를 모두 보여준다 |
| D8 | 기존 엑셀 가격은 모두 VAT별도다. 이관할 때 **VAT포함(×1.1)으로 변환해 기입**하고, 화면에는 **VAT별도/VAT포함 보기 전환**을 둔다 |
| D9 | PM 원료금액에 곱한 계수는 **비중**이다(kg 단가 → ml/L 판매 단위 환산). 구제조법 원가에는 비중이 이미 반영되어 있다. 신규 배합을 만들 때 **비중 계산 단계**를 넣는다 |

## 1. 구성

```
Documents\MiniERP2\                 (기존 저장소, GitHub 동일)
├─ MiniERP2.csproj                  기존 ERP
├─ MFG\MiniERP2_MFG.csproj          ★ 신규 단독 실행 프로젝트 (WinForms .NET 10, 같은 패키지: Sqlite·EPPlus)
├─ Tests\ ...                       MFG 테스트도 여기(또는 MFG.Tests)
└─ MiniERP2.slnx                    두 프로젝트 모두 포함
```

- **같은 저장소 안의 별도 프로젝트**로 둘 것을 권장한다.
  - 장점: GitHub 푸시와 백업이 한 곳으로 모이고, MiniERP2가 MFG 실행 파일 위치를 쉽게 안다.
  - MFG는 MiniERP2 프로젝트를 참조하지 않는다. 독립 빌드되므로 MiniERP2 코드를 고쳐도 MFG가 깨지지 않는다.
  - 백업 서비스 같은 공통 패턴은 MFG 쪽에 같은 방식으로 따로 구현한다.
- 데이터 위치는 MiniERP2 방식(2026-09-04 사고 이후 %AppData% 사용)을 따른다.
  - `%AppData%\MiniERP2_MFG\mfgdb.sqlite`
  - `%AppData%\MiniERP2_MFG\settings.json`
  - `%AppData%\MiniERP2_MFG\Backups\`
- 백업은 MiniERP2 `DbBackupService`와 같은 규칙으로 한다.
  - 수동/작업 전 백업: 최신 3개 유지
  - 일일 백업: 2개월 유지
  - 월간 백업
  - 복원 기능
  - 스키마 변경은 `CREATE TABLE IF NOT EXISTS` + 열 추가 마이그레이션(MiniERP2 `DbSchema` 방식)

## 2. MiniERP2 연동 (3가지)

| 방향 | 내용 | 시점 |
|---|---|---|
| MiniERP2 → MFG 실행 | 메인 허브에 "제조원가(MFG)" 버튼을 추가해 `MiniERP2_MFG.exe`를 실행한다. 이미 실행 중이면 그 창을 앞으로 가져온다. 실행 파일 경로는 MiniERP2 설정에 두고, 기본값은 빌드 산출물 위치다 | 1차 |
| MiniERP2 → MFG 매입처 | MiniERP2 DB의 `SalesChannelTable` 중 `IsPurchase=1`인 채널(현재 24곳)을 **읽기 전용**으로 불러와 mfgdb 매입처 목록에 동기화한다(코드 + 이름 사본). MFG 원료/부자재 단가에는 이 **채널코드**를 기록한다. 채널 신규 등록은 MiniERP2에서 한다 | 1차 |
| MFG → MiniERP2 원가 전송 | **확정된** 완제품만 SKU 기준으로 `ItemTable.CostPrice`(VAT포함)에 반영하고 `ItemCostHistory`에 이력을 남긴다. 변경 전/후 미리보기 → 선택 → 전송 순서이고, 전송 직전에 MiniERP2 DB를 자동 백업한다 | 1차 |
| (나중) 원료 매입가 → MiniERP2 `PurchaseSkuTable` | 견적/매입 기능과 공유가 필요할 때 추가 | 보류 |

- MiniERP2 DB 경로는 기본값 `%AppData%\MiniERP2\ERP_Database.sqlite`이고 MFG 설정에서 바꿀 수 있다. 경로가 없으면 MFG는 연동 기능만 비활성화하고 단독으로 동작한다.

## 3. 데이터 모델 (mfgdb)

### 3-1. VAT 처리 (D8)
- 모든 단가는 **VAT포함 금액으로 저장**한다. MiniERP2 `CostPrice`(VAT포함)와 기준이 같다.
- 원료와 부자재마다 `과세/면세` 구분을 둔다. 기본값은 과세다.
- 화면 상단의 [VAT포함 | VAT별도] 전환은 표시용이다. VAT별도 보기는 과세 항목만 ÷1.1 한다.
- 단가 입력칸도 현재 보기 기준으로 받는다. VAT별도 보기에서 1000을 입력하면 1100으로 저장한다.
- 기존 엑셀 값을 가져올 때는 ×1.1 해서 저장한다. 반올림하지 않고 원 단위 소수를 유지한다. 그래야 VAT별도 보기로 바꿨을 때 원래 엑셀 숫자와 정확히 같아진다.

### 3-2. 테이블
| 테이블 | 주요 칼럼 |
|---|---|
| `Supplier` 매입처 | ChannelCode(PK, MiniERP2 채널코드), 이름, MiniERP2에서 동기화한 시각, MFG 전용 메모 |
| `Material` 원료 | Code(**자동 채번** `RM0001`~), 원료명, 별칭 목록(구 표기명), 전성분명, CAS, 역할, **비중**, 혼합물 여부, 과세 여부, 상태(사용/중지), 비고 |
| `MaterialPrice` 원료 매입가 이력 | 원료, 매입처(ChannelCode, 없을 수 있음), 단가(VAT포함, **원/kg**), 적용일, 출처(견적/명세서/엑셀이관/사용자확정), **확실도**(확정/불확실), 메모 |
| `MaterialComponent` 혼합물 구성 | 혼합 원료 → 전성분명·CAS·비율 |
| `PackMaterial` 부자재 | Code(자동 `PK0001`~), 분류(용기/캡/라벨·스티커/단상자·박스/기타), 품명·규격, 매입처, 과세 여부 |
| `PackMaterialPrice` 부자재 단가 이력 | 부자재, 매입처, 단가(VAT포함, 원/개), 적용일, 출처, 메모 |
| `Recipe` 제조법(배합) | Code(`C/S/H/D`+번호, 자동 채번), 제품명, 버전명, 원본(엑셀 시트명), **상태(미확정/확정)**, 확정일, 확정 메모, 실측 비중, 계산 비중, 배치 생산량, 공정 메모 |
| `RecipeLine` 배합 행 | 제조법, 순서, 단계, 원료, 투입량(wt%), 공정 메모 |
| `RecipeSize` 용량별 완제품 | 제조법, 용량(ml), 충진중량 = 용량 × 적용 비중, 임가공비, 검사비, 기타비, 메모 |
| `RecipeSizePack` 용량별 부자재 | 용량, 부자재(또는 직접 입력 금액), 수량 |
| `RecipeConfirmLog` 확정 이력 | 확정 시점의 kg당 원료비·용량별 원가·적용 단가를 **그대로 저장한 스냅샷**. 나중에 단가가 바뀌어도 그때 왜 그 원가였는지 추적할 수 있다 |
| `FinishedProduct` 완제품(SKU) | MiniERP2 SKU, 상품명, 구성 유형(배합 용량 / 원료 소분 / 묶음 / 외부 매입 / 수동값), 연결 대상, 추가 비용(패키지·스티커·기타·택배비 배분), 상태(미확정/확정), 마지막 전송 원가와 시각 |
| `FinishedProductComponent` 묶음 구성 | 묶음 SKU → 구성 SKU × 수량 |

- **현재 단가**는 원료의 가장 최근 적용일 단가로 정한다. 매입처가 여럿이면 "기본 매입처"를 지정할 수 있다.
- 원료 단가가 바뀌어도 확정된 제조법의 원가는 자동으로 바뀌지 않는다. 대신 "확정 후 단가 변동 있음" 표시를 띄워 다시 확인하고 재확정하도록 한다.
- 확정된 제조법의 배합을 수정하면 자동으로 미확정으로 돌아간다. 이전 확정본은 `RecipeConfirmLog`에 남는다.

## 4. 화면

메인 창 탭 구성: **원료 / 부자재 / 매입처 / 제조법 / 완제품 원가 / MiniERP2 전송 / 설정·백업**. 상단에는 항상 [VAT포함|VAT별도] 전환과 미확정 건수를 표시한다.

1. **원료**: 목록·검색(원료명, 별칭, CAS, 코드). [신규 원료]는 코드를 자동 부여하고 같은 이름이나 별칭이 이미 있으면 경고한다. 오른쪽 패널에 매입처별 단가 이력과 [단가 추가], 이 원료를 쓰는 제조법 목록을 보여준다.
2. **부자재**: 원료와 같은 구조(원/개 단가).
3. **매입처**: MiniERP2에서 동기화한 채널 목록, [MiniERP2에서 다시 불러오기], 매입처별 원료·부자재 목록.
4. **제조법**: 제조법관련 엑셀 시트 틀을 그대로 옮긴 편집 화면.
   - 왼쪽: 제조법 목록. 미확정/확정 필터와 C/S/H/D 분류 필터를 둔다.
   - 상단: 제품명, 버전, 원본 시트, **[확정] / [미확정으로]** 버튼, 상태 배지.
   - 배합표: 원료(검색 드롭다운; 없으면 그 자리에서 신규 등록), 투입량%, 단가(원/kg), 원료비(원/kg 제품). 합계가 100%인지 검증한다.
   - **비중 단계**(D9): 원료 비중으로 계산 비중을 자동 산출하고, 실측 비중을 입력하면 실측값을 우선 적용한다. 원료 중 비중 미입력이 있으면 표시한다.
   - 결과: **kg당 원료비**, L당 원료비(= kg당 × 비중).
   - **용량별 완제품 단가표**(D7): 열 = 용량(개수 제한 없음, 열 추가 가능). 행 = 충진중량 → 원액비 → 용기/캡/라벨/박스/기타 부자재 → 임가공·검사·기타 → **완제품 단가**, ml당 단가.
   - [다른 이름으로 복사(새 버전)], [배치 계량표](배치 kg 입력 → 원료별 g), 전성분(함량순) 미리보기.
5. **완제품 원가**(PM 대체): MiniERP2 SKU 목록. 열 구성은 PM과 같다(원료 / 용기 / 패키지 / 스티커 / 기타 / 택배비 → 합계). 각 SKU를 제조법 용량, 원료 소분, 묶음, 외부 매입, 수동값 중 하나에 연결한다. 연결된 원가와 MiniERP2 현재 원가의 차이를 표시하고 SKU별로 [확정]한다.
6. **MiniERP2 전송**: 확정 SKU 중 MiniERP2 원가와 다른 것만 목록으로 보여준다(전/후/차이). 체크한 것만 전송한다.
7. **설정·백업**: MiniERP2 DB 경로, 백업 목록·복원, 기본값(수수료율 등은 나중에).

## 5. 초기 데이터 세팅 (모두 미확정으로)

| 순서 | 원천 | 대상 | 처리 |
|---|---|---|---|
| 1 | MiniERP2 `SalesChannelTable` IsPurchase=1 | Supplier | 24곳 동기화 |
| 2 | 신제조법 `원료목록` 136종 | Material + MaterialPrice | 기존 코드 RM001~ 유지(신규는 이어서 채번), 단가 ×1.1, "단가 확실치 않음" 원료는 확실도=불확실 |
| 3 | 신제조법 `단가이력` 약 350건 | MaterialPrice(이력) | 출처 시트명을 메모에 기록, ×1.1 |
| 4 | 신제조법 `혼합물구성` | MaterialComponent | |
| 5 | 신제조법 배합 시트 61개 (제조법관련 틀) | Recipe / RecipeLine / RecipeSize / RecipeSizePack | 원본 시트명과 시트 메모를 보존한다. 부자재 금액은 이름이 부자재 목록과 맞으면 연결하고, 아니면 직접 입력 금액으로 넣는다 |
| 6 | PM `기타(부자재)` 57행 | PackMaterial + 단가 | 품명 앞 "동방, / 청진, / 다담, …"을 매입처 채널(동방플라스틱 CH050, 청진 CH052, 다담피앤씨 CH056 등)과 자동 연결한다. 애매하면 연결하지 않고 비워 둔다 |
| 7 | PM 판매 품목 약 575 SKU | FinishedProduct | **처음에는 PM 현재 값 그대로 "수동값"으로** 넣는다. 그래서 첫날 MiniERP2와 원가가 같다. 이후 확인한 SKU부터 제조법에 연결하고 확정한다. 초안 §5의 대응표를 "연결 후보"로 미리 띄워 준다 |

- 구제조법에만 있는 시트(`고체연료(개발중)`, `블루버드(원본0`, `Sheet3 원본`, `영업관련 메모`)는 1차 이관에서 제외한다. 필요하면 나중에 개별로 가져온다.
- 원본 엑셀 파일은 읽기만 한다.

## 6. 개발 단계

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| **M0** 골격 | MFG 프로젝트, mfgdb 스키마·마이그레이션, 백업(수동/일일/월간/복원), 설정, 메인 창 틀 + VAT 전환 | 실행되고 DB·백업 파일이 생성됨, 테스트 통과 |

## 7. 확인 요청 (짧게)

- **Q1. 비중 계수가 안 맞아 보이는 PM 행.**
  - 피마자유는 `×1.03`이 쓰였다. 피마자유 비중은 약 0.96이라, 1L 원가라면 ×0.96이어야 할 것 같다.
  - 비타민E 100ml는 `49500×1.25×0.1`이다. 토코페릴아세테이트 비중은 약 0.96이다.
  - 다른 이유(로스·운임 등)가 섞인 행일 수 있다. 이관에는 영향이 없다(PM 값을 그대로 가져옴). 나중에 해당 SKU를 연결할 때 확인하면 된다.
- **Q2. 면세 원료가 있는지.** 없으면 전부 과세로 둔다.
- **Q3. MiniERP2로 보내는 원가 범위.** 지금 PM은 일부 SKU 원가에 택배비·입고비(P열)까지 포함해서 MiniERP2에 들어간다. MFG도 PM과 같이 "택배비 포함 합계"를 보낼지?
- **Q4. 위치.** MiniERP2 저장소 안 `MFG\` 폴더(권장)로 해도 되는지, 아니면 ParcelSorter처럼 별도 폴더·저장소를 원하는지?

## 8. 진행 현황 (2026-10-21)

구현하면서 정한 것:
- **원료목록 단가의 적용일 = 신제조법 작성일(2026-10-20).** 원래 입력일을 적용일로 쓰면, 단가이력에 있는 그보다 늦은 날짜(예: "2026-06")의 옛 시트 기록이 현재 단가로 잡혀 19개 배합 원가가 엑셀과 달라졌다. 원래 입력일은 단가 메모에 남겼다.
- **배합 시트에 직접 입력된 단가(S04)는 원료 단가로 옮기지 않았다.** 같은 원료를 S06은 단가 없이 계산하므로, 옮기면 S06 원가가 엑셀과 달라진다.
- **완제품은 처음에 PM 값 그대로 "수동값"으로 가져왔다.** 첫날 MiniERP2 원가와 같게 시작하기 위함이다. 제조법 연결은 자동으로 하지 않고 "연결 후보"로만 보여 준다. PM 원료 열에 부자재가 포함됐는지가 품목마다 달라(핸드워시는 단품 전체, 화장품은 원료만) 자동 연결하면 이중 계산될 수 있기 때문이다.
- **SKU 칸에 메모가 들어간 PM 행**(한글·공백 포함)은 SKU 없이 가져오고 메모는 비고로 옮겼다. 중복 SKU도 같은 방식으로 처리했다.
- **매입처 자동 연결은 부자재 57개 중 31개만 됐다.** 국일·대동·지에프 등은 MiniERP2 매입 채널에 없고, "박스_…"는 거래처 표기가 없다. 부자재 탭에서 지정해야 한다.
